## 两个清理切点

真实 Codex 会话提交 Host 固定的文件快照引用。Run 仍在等待下一任务且 State 引用文件时，受权清理保留原快照。第二个真实会话完成任务，测试工作流通过程序指定字段将 State 的引用清空。监督进程分别在下列持久化边界停止普通 Host 清理子进程。

| 切点 | 文件样本 | 强杀与恢复的断言 |
|---|---:|---|
| 清理任务已持久入队、快照尚在 | 262,144 B | Outbox 正文已删除，队列及审计已提交，快照为 `acked`。重启后删除快照并出队。 |
| 快照行已删除、清理任务尚未出队 | 2,093,056 B | 强杀后快照仍不存在，队列仍有原任务。重启识别快照已删除并完成出队。 |

两次恢复都应保留一次原清理审计，重复清理无待处理任务，受权历史 Ack 仍为原 revision 4。Checkpoint、Journal 和接纳索引均需保持一致。进程终止发生在产品原有清理调用的外层受信回调边界。

## 运维演练

- **跨 Store 撤销。** 每个平台用两个独立 Store 和同一测试公钥。A 应用撤销后进入部分完成状态。B 的未授权操作失败且 B 仍有效，演练保持未完成状态。对 B 授权重试后，逐库核对旧签名拒绝及历史接纳索引。测试监督器记录待确认和已确认清单。
- **容量告警。** 用真实模型工具分别触发记录数和逻辑字节上限，核对每次拒绝都有 Host 告警，事件含 namespace、当前用量和生效上限；Pending、Journal 和接纳索引不变。告警记录在受保护的本地日志。
- **物理占用。** 记录 Run、Outbox、文件交接三个数据库及当时存在的 WAL／SHM 文件长度。另记录运行时返回的已分配块字节。采样点为新库、已写快照、强杀边界和清理恢复后。该采样反映测试文件，不包含目录元数据、生产日志、备份和磁盘总余量。

## 生产参数建议

这些是部署压测起点，沿用现有示例的初始值，尚未冻结。

| 参数 | 建议 |
|---|---|
| 已对账正文保留窗口 | 对已终态、已对账且没有保留标记的正文，先以 30 天评估。窗口起点采用 Ack 落盘时间。未对账记录、有效引用、合规保留及 Store 接纳索引按既有保护规则处理。独立审计记录的期限由发布部署的审计政策决定。 |
| Outbox 逻辑配额 | 每个 Host Outbox 先以 64 MiB 或 4,096 条先到为上限做压测。按每个 Outbox 的高峰日写入量乘以保留天数，再加未对账积压和待清理引用，对条数与字节分别做预算。 |
| 磁盘预算和告警 | 对数据库、WAL、SHM、文件快照、审计和备份合计设置独立磁盘预算。以压测的峰值加恢复余量定额。可先在逻辑和磁盘预算达到 70% 发预警、85% 升级；触及硬上限维持已有拒绝与告警。 |
| 手工清理 | 保留每日检查和受权清理。逻辑记录删除后，SQLite 文件可能保留已分配页供后续复用。需要释放卷空间时另安排维护窗口和受控压缩操作，并在同一卷上验证空间回收和恢复。 |

生产全量 Store 清单、暂停入口的外部控制、集中告警送达、最终磁盘预算及保留策略仍待部署验证。

正式协调时，以批准的 Host／Store 清单为撤销目标并记录逐项结果。先暂停仍可能用旧钥签发的入口，逐库执行并验证，全部确认后才恢复入口。本轮仅演练确认清单和部分失败处理，生产入口联动为 BLOCKED。

## 备份恢复预演

把 Run Store、Outbox 及启用时的文件交接库和快照纳入同一恢复点。对使用 SQLite 的部署，先停止相关写入，再分别生成一致副本，记录文件 SHA-256 及受保护的策略和密钥版本引用。恢复到新路径，按 R5 校验数据库完整性、Checkpoint、Journal、程序字节与接纳索引，并对照原 Ack 和待对账记录。将已撤销密钥的状态纳入恢复后的信任核对。

实验环境已验证停写后的 Store 和 Outbox 成对恢复。实际备份系统、文件交接与快照、部署密钥策略及恢复窗口仍待验。 [成对恢复命令与日志](./staging-joint-r5.md)
