### 本批增量证据

- **R11（C06/C15）**。测试在 SQLite 提交后丢弃 CAS 响应。另一条独立连接恢复并推进到终态。重放原收据返回首次接纳的 revision 6 和最新 revision 34，Journal 仍是 35 条，Checkpoint 与 Journal 无额外写入。该回归覆盖现有 SQLite 的重放恢复路径，R03 中弱一致自定义 Store 的拒绝仍随 CF-06 待裁决。
- **C20**。两个不同 PID 的 Node 进程经测试屏障提交不同的有效 Ed25519 签名结果。一个提交成为该 Pending 的唯一持久收据，另一进程得到 `FK_I_RECEIPT_CONFLICT`。真实生成程序继续推进到终态。
- **R12 / A-M6-06**。同一份 300-Agent 生成 JS 在预算 1 和 128 下分别完成 5,104 和 2,102 次成功 CAS。终态 State 摘要相同。重开后全部 300 条回执仍可查询，最近回执缓存为 16，最早 Ack 可原样重放。Windows 本地样本的累计序列化 Checkpoint 为 131,096,840 / 53,999,464 B，采样 WAL 高水位约 4.19 MB，关库后 WAL 为 0。脚本记录提交次数、延迟分位、Checkpoint/Journal/Receipt 大小、数据库和 WAL 采样。逻辑序列化量和采样文件长度用于量化存储成本，设备层实际写入量与生产 SLA 仍未测量。
- **S14 / A-M6-02**。包验证从实际安装的 tarball 使用最低 TypeScript 5.0.4 导入 `@devcodex-labs/flowkit/interactive`。正例编译真实声明，负例检查公开终态的 State 不可读、结果引用拒绝错误协议版本。Standard、ESM/CJS、CLI、类型及 docs 消费仍由原有验证覆盖。

### 集中裁决

| 待决定项 | 建议和实际影响 |
|---|---|
| 第三批原生宿主目标 | 在保留 Grok 为冻结目标、等待明确授权后做真实复验，与批准新宿主并重新冻结等价验收条款之间选择。当前两种路径都需要真实 Pending、签前输入和会话绑定、独立 OS 身份及终态证据。 |
| 大入参可信协议 | 优先选择宿主可独立观察完整规范字节的事件模式。若目标只给文件引用，可单独批准并评审由受保护 Host 固定不可变字节和摘要的协议，验证同字节、时序、超限、替换和失配。 |
| CF-01 管理终止 | 在 R5 的版本化 Store 迁移和独立管理审计，与批准现有 Journal 承载等价管理审计之间选择。两者都需处理旧版读取 `cancelled` 和竞态。 |
| CF-02/05 SDK 与公开帧 | 推荐保留旧 factory 作为可信 Host 入口，新增 R5 顶层 API 和通用安全帧。若要退役旧帧，需要明确调用方的迁移窗口。 |
| CF-06 Store | 推荐先加 R5 异步五操作与独立 Registry 接缝，兼容同步 factory。统一迁移则需明确版本和旧 Store 的退场方案。 |
| ABI-01 转移身份 | 推荐旧 Run 保留原公式，新 Run 用版本化 R5 公式。历史迁移需要另审对账与回执兼容。 |

跨 Node/OS 搬移同一数据库仍按 C21 原定义属于增强项。正式验收及复审完成之前，PR 保持 Draft。
