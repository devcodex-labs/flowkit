# 构建并部署工作流

从源码构建AOT，复制到独立部署目录，验证正常运行、改源失配和缺源失败，再重新构建恢复。部署的文件组合包括源码、产物、宿主、依赖声明和Skill。

## 按顺序运行

命令在本例根目录逐行执行，cd之后按命令进入目标目录。带故意失败参数的命令是独立验证步骤，记录错误后继续恢复操作。

```sh
node deploy.mjs
cd deployment
npm install --ignore-scripts --no-audit --no-fund
node host.mjs
```

## 对照预期结果

deploy.mjs在构建目录先compile，再复制六类文件到deployment；该目录显式安装FlowKit 1.0.0后，host运行sample.compiled.mjs，返回succeeded/done和读取到的Skill内容。mmd用于查看，执行不依赖它。

## 失败与恢复

在deployment/sample.workflow.js末尾追加注释，再node host.mjs，应得到FK_R001。回到构建目录重新node deploy.mjs，回deployment运行恢复。再将部署源码临时重命名为sample.workflow.js.bak，运行应因缺源得到FK_R001；恢复原名后成功。重命名前确认没有同名备份，避免覆盖。

## 接入真实业务

把deployment复制到目标机器的全新目录，按确切版本安装依赖，再检查版本和执行。不要依赖构建目录的上层node_modules。生产自动化使用锁文件npm ci；保持source相对布局，不移动产物而遗漏源码。AOT验证不是恶意代码沙箱。

## 完成标准

你应能运行成功路径、观察上述反例并恢复成功，解释状态字段及对应控制流。PowerShell用$LASTEXITCODE、Bash用echo $?查看上一条命令退出码。源码修改后重新compile/check，不继续使用不匹配的旧产物。继续阅读[相关契约](/guide/aot)，或回到[选择示例](/examples/index)。
