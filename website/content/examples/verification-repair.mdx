## 按顺序运行

命令在本例根目录逐行执行，cd之后按命令进入目标目录。带故意失败参数的命令是独立验证步骤，记录错误后继续恢复操作。

```sh
npx --no-install flowkit compile sample.workflow.js
npx --no-install flowkit check sample.workflow.js
node host.mjs
node host.mjs exhaust
```

## 对照预期结果

默认target=1：events为check:0、repair:1、check:1，result为succeeded/done，score=1。exhaust使用target=9：检查3次、修复2次，最后failed/failed且score=2。failed终点是正常resolve，本宿主仍正常退出。

## 失败与恢复

将maxIterations临时改成1再运行exhaust，应只有check:0，没有repair，直接failed。恢复3，重新compile/check并复跑两种模式。若body改成improve，会得到FK_C041；恢复check这个verification入口。

## 接入真实业务

替换runVerification为业务质量判断，替换runAction为可重复的修复操作。最后一轮失败不再修复；不要把maxIterations误解为修复次数。修复涉及外部写入时保证幂等。

## 完成标准

你应能运行成功路径、观察上述反例并恢复成功，解释状态字段及对应控制流。PowerShell用$LASTEXITCODE、Bash用echo $?查看上一条命令退出码。源码修改后重新compile/check，不继续使用不匹配的旧产物。继续阅读[相关契约](/dsl/loop)，或回到[选择示例](/examples/index)。
