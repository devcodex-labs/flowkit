# 兼容与支持范围

本页区分使用FlowKit包和维护文档站的环境，避免把站点工具链要求当成SDK最低版本。

| 项目 | v1.0.0范围 |
|---|---|
| SDK/CLI运行时 | Node.js >=22.13.0，ESM |
| 工作流源文件 | .workflow.js或.workflow.ts，可静态提取DSL |
| AOT入口 | .compiled.mjs，保留对应源码与Skill布局 |
| TypeScript声明 | TypeScript 5.0+，使用const类型参数 |
| 文档站开发 | Node >=24，website独立依赖与锁文件 |
| 文档语言 | 简体中文；当前没有英文翻译版本 |
| 授权 | 专有授权；详见 LICENSE，包由 GitHub Packages 私有分发 |

## 自动检查的环境

仓库CI配置Ubuntu 24.04和Windows 2025，分别使用Node 22.13.0与24.22.1，共四组包检查与文档消费者任务。网站构建任务使用Ubuntu 24.04/Node 24.22.1。配置矩阵表示维护目标，某次提交是否通过应查看该提交真实CI结果。

不能把Node版本声明或本机成功扩大为所有操作系统、浏览器、模型SDK都经过验证。生产宿主的模型服务、审批UI、存储和网络客户端由项目方选择并验证。

## 已有能力与宿主责任

FlowKit提供静态DSL编译、图和数据声明检查、可读生成代码、Mermaid、进程内执行、公开Runtime接缝。模型调用、完整JSON Schema校验、业务权限、持久化状态、跨进程恢复、部署和监控均由宿主承担。

并行共享state；any不自动取消其余分支。初始state只做顶层浅复制。默认Skill loader有范围、白名单、完整性和读取限制，自定义loader自行承担对应责任。AOT完整性验证不是执行沙箱。

## 版本与升级

仓库当前版本为1.0.0，实际发布状态须核对 Git Tag 与 GitHub Packages。消费者建议精确安装并提交锁文件，先在独立环境运行自己的关键流程，再升级生产。工作流自己的version与包版本独立。升级后重新compile/check，旧产物的版本、生成逻辑或选项可能不同，不应直接继续手工拼接使用。

报告兼容问题时提供实际Node/npm/系统版本、包版本和最小复现，见[问题定位](/troubleshooting/index)。当前能力清单见[发布记录](/community/changelog)。

## capability-graph 兼容性

可选 Provider 与宿主动作适配使用独立的 `@devcodex/capability-graph` v2.1.1 SDK 契约。核心六个 SDK 与八类 DSL 节点不变；Graph 的 Provider schemaVersion、声明版本、结果 revision 不等于 FlowKit 版本。Graph 可能与 Node 20 兼容，但 FlowKit 仍要求 Node >=22.13.0；消费者按两者要求取交集。

文档站已获批准公开展示；FlowKit 源码仓库与 GitHub Packages 安装包仍是私有的。站点公开不代表源码开源或授予包下载权限；GitHub Pages 实际可用性和发布授权需在部署时单独核查。
