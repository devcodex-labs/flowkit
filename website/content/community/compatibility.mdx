本页记录 FlowKit 1.0.0 已有支持条件。计划中的 DSL、Workflow Skill 兼容或旧 Run 迁移须以对应版本的已验收文档为准。

本页区分使用FlowKit包和维护文档站的环境，避免把站点工具链要求当成SDK最低版本。

| 项目 | v1.0.0范围 |
|---|---|
| SDK/CLI运行时 | Node.js >=22.13.0，ESM |
| 工作流源文件 | .workflow.js或.workflow.ts，可静态提取DSL |
| SDK AOT入口 | .compiled.mjs，保留对应源码与Skill布局 |
| 直接生成模块 | 本版所选Standard节点由Host自供Ctx/Runtime；见[直接执行](/guide/direct-host)，与SDK AOT校验不同 |
| Interactive | P0-A、P0-B、P1 和 P2 Host/Store 协议。参考 SQLite 实现使用 node:sqlite。见[接口分层](/guide/interactive) |
| TypeScript声明 | TypeScript 5.0+，使用const类型参数 |
| 文档站开发 | Node >=24，website独立依赖与锁文件 |
| 文档语言 | 简体中文；当前没有英文翻译版本 |
| 授权 | 专有授权；详见 LICENSE，包由 GitHub Packages 私有分发 |

## 自动检查的环境

仓库CI配置Ubuntu 24.04和Windows 2025，分别使用Node 22.13.0与24.22.1，共四组包检查与文档消费者任务。网站构建任务使用Ubuntu 24.04/Node 24.22.1。配置矩阵表示维护目标，某次提交是否通过应查看该提交真实CI结果。

不能把Node版本声明或本机成功扩大为所有操作系统、浏览器、模型SDK都经过验证。生产宿主的模型服务、审批UI、存储和网络客户端由项目方选择并验证。

## 已有能力与宿主责任

Standard 提供静态 DSL 编译、图和数据声明检查、可读生成代码、Mermaid、进程内执行和 Runtime 接缝。模型调用、完整 JSON Schema 校验、业务权限、部署和监控由宿主负责。Interactive 由可信 Host 管理 SQLite 持久化与跨进程续跑。P0-B 增加持久 Action、Verification、Human 和 Loop，P1 支持全部分支成功再合并，P2 支持首个合格分支胜出、取消及对账。适用节点和接入方式见 [Interactive 接入](/guide/interactive)。Author 可为 Standard 和上述各 Interactive 阶段生成可复审候选，见[起草指南](/guide/workflow-authoring)。

Standard 的并行分支共享 state，`any` 汇合后其余分支仍可继续。初始 state 做顶层浅复制。默认 Skill loader 有范围、白名单、完整性和读取限制，自定义 loader 自行承担对应责任。AOT 完整性验证与执行隔离由各自的机制负责。

## 版本与升级

仓库当前版本为1.0.0，实际发布状态须核对 Git Tag 与 GitHub Packages。消费者建议精确安装并提交锁文件，先在独立环境运行自己的关键流程，再升级生产。工作流自己的version与包版本独立。升级后重新compile/check，旧产物的版本、生成逻辑或选项可能不同，不应直接继续手工拼接使用。

报告兼容问题时提供实际Node/npm/系统版本、包版本和最小复现，见[问题定位](/troubleshooting/index)。当前能力清单见[发布记录](/community/changelog)。

## capability-graph 兼容性

可选 Provider 与宿主动作适配使用独立的 `@devcodex/capability-graph` v2.1.1 SDK 契约。FlowKit 根入口有八个 SDK 导出。Graph 的 Provider schemaVersion、声明版本、结果 revision 分别独立于 FlowKit 版本。消费者需满足两者的 Node 要求，FlowKit 要求 Node >=22.13.0。

文档站已获批准公开展示；FlowKit 源码仓库当前公开可见但采用专有许可，GitHub Packages 安装包仍私有分发。站点公开不代表源码开源或授予包下载权限；GitHub Pages 实际可用性和发布授权需在部署时单独核查。
