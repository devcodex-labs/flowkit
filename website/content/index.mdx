## 适合你的任务吗

当任务包含多个业务步骤，并需要明确的分支、校验、重试或人工决策时，可以用 FlowKit 组织控制流。你仍需提供实际模型或业务服务，以及适合业务的结果校验器。

本站快速开始使用 Standard，它在进程内执行完整流程。并行分支共享状态，`any` 汇合后其他分支仍可继续执行。需要持久化暂停和跨进程续跑时，内部维护者可评估 Interactive P0-A 及其可信 Host 和 SQLite Store。模型服务和审批界面由宿主提供。[宿主接入与模式范围](/guide/host-integration)

需要在宿主中发现已声明的 FlowKit 能力时，先查看[能力和文档读取](/guide/capability-provider)，再按[宿主消费示例](/examples/capability-graph)提供明确绑定。

[项目介绍](/guide/introduction) · [安装与环境](/guide/installation) · [授权与使用](/community/license)

需要能力发现或跨 Provider 依赖判断时，可选用[FlowKit Provider 声明](/guide/capability-provider)与[capability-graph 宿主示例](/examples/capability-graph)；它们不改变现有 DSL 的控制流执行契约。

## 对外服务方向

FlowKit 是私有工作流基础设施，拟通过 **MCP 服务、托管 API 或付费工作流设计产品** 对外提供工作流能力，而不是向付费客户交付 npm 包。以上是计划中的商业化方向，**目前未提供可直接购买或调用的正式服务**。

本站文档允许公开阅读；FlowKit 源码仓库当前公开可见，采用专有许可；软件包仍按私有 GitHub Packages 分发，内部部署环境另行授权。公开可见不等于开源，也不自动授予安装、使用或分发权利。未来客户取得的生成工作流产物使用权，将由单独的产品服务条款明确。


准备自己编写或接入时，先读[能力选型与编写路径](/guide/workflow-authoring)，再选择[Standard宿主](/guide/host-integration)、[直接执行编译JS](/guide/direct-host)或[Interactive](/guide/interactive)。
