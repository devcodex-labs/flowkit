# 安装与环境

本页从一个空目录安装 FlowKit v1.0.0，确认导入和命令行可用。使用 SDK 不需要克隆 FlowKit 仓库，也不需要安装文档站依赖。

## 前置条件

- Node.js **22.13.0 或更高版本**，包含 npm。
- 一个可写的本地目录，以及访问 npm registry 的网络连接。
- 示例宿主使用 `.mjs`，工作流使用 `.workflow.js`；它们遵循 ESM 导入方式。

先检查实际环境：

```sh
node --version
npm --version
```

Node 版本低于最低要求时，先升级并确认终端正在使用新版本。文档站贡献者需要 Node >=24，这是站点构建环境，和 SDK 的最低版本分开。

## 创建项目并精确安装

以下命令可用于 PowerShell 和常见 POSIX shell；每行分别执行。

```sh
mkdir flowkit-demo
cd flowkit-demo
npm init -y
npm pkg set type=module
npm install --save-exact @devcodex-labs/flowkit@1.0.0
```

`--save-exact` 让 package.json 保存明确版本。保留 npm 生成的 package-lock.json，在其他机器上用 `npm ci` 安装一致的依赖。

确认包身份：

```sh
node --input-type=module -e "import p from '@devcodex-labs/flowkit/package.json' with {type:'json'}; console.log(p.name, p.version)"
```

预期为 `@devcodex-labs/flowkit 1.0.0`。如果显示其他版本，检查当前目录的 package.json、lock 文件和 `npm ls @devcodex-labs/flowkit`，不要仅根据全局安装结果判断。

## 公开导入入口

```js
import { run, compile, compileSource, check, evalWhen, isControlSignal } from '@devcodex-labs/flowkit';
import { defineWorkflow, node, action, verification, parallel, condition, loop, human, terminal } from '@devcodex-labs/flowkit/dsl';
```

根入口提供 SDK，`/dsl` 提供定义构造器。不要从包的内部 `src` 或 `dist` 子路径导入。安装后的 `flowkit` 可执行命令只有 `compile` 和 `check`；执行工作流由宿主调用 SDK 的 `run`。

## 准备文件目录

```text
flowkit-demo/
  package.json
  package-lock.json
  node_modules/
  sample.workflow.js    ← 下一页创建
  host.mjs              ← 下一页创建
```

工作流源码必须使用 `.workflow.js` 或 `.workflow.ts` 后缀。`workflow.js` 不满足这个约束。默认编译产物保存在源码旁；不需要先创建 dist 目录。

## 常见安装问题

| 现象 | 检查与处理 |
|---|---|
| 找不到 `node` / `npm` | 在新终端检查 PATH，确认安装的 Node 版本；先让版本命令可执行 |
| registry 超时或无法访问 | 检查网络和 `npm config get registry`；公共包地址为 registry.npmjs.org |
| `ERR_MODULE_NOT_FOUND` | 在有 package.json 的消费者目录安装，确认 host 文件位于该项目内 |
| `ERR_PACKAGE_PATH_NOT_EXPORTED` | 改用上面的三个公开入口，不访问内部文件 |
| CLI 命令不存在 | 在已安装包的目录使用 `npx --no-install flowkit ...`；此写法不会偷偷下载其他版本 |
| 版本不存在或安装内容不匹配 | 保留错误与registry信息，核查精确版本；不要把未成功的安装当成可运行环境 |
