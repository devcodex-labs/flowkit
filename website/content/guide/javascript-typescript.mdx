# JavaScript 与 TypeScript

FlowKit v1.0.0 使用同一套 DSL 编译 JavaScript 与 TypeScript。选择你项目已经使用的语言即可；两者生成相同的控制流语义。先完成[安装](/guide/installation)，确保消费者项目是 ESM。

## 文件名与入口

工作流必须以 `.workflow.js` 或 `.workflow.ts` 结尾，并从 `@devcodex-labs/flowkit/dsl` 导入构造器，默认导出 `defineWorkflow(...)`。宿主可以是普通 `.mjs`，从 `@devcodex-labs/flowkit` 调用 SDK。这两个入口都属于公开接口，不需要导入 dist 内部文件。

## TypeScript 检查和执行是两步

类型声明使用 const 类型参数，需要 TypeScript 5.0 或更新版本。可以在独立项目安装 TypeScript，再执行类型检查：

```sh
npm install --save-dev typescript@5.0.4 @types/node@22.13.0
npx tsc --noEmit --strict --skipLibCheck --target ES2022 --module NodeNext --moduleResolution NodeNext sample.workflow.ts
npx --no-install flowkit compile sample.workflow.ts
npx --no-install flowkit check sample.workflow.ts
```

`tsc` 验证 TypeScript 声明和静态引用。FlowKit 编译器另行检查节点数量、可达性、受限回边、Skill 路径等。类型检查成功并不代替 compile/check。FlowKit 不要求你先把 `.workflow.ts` 编译成 JavaScript，也不执行其中任意顶层代码。

## 保持工作流为可静态提取的字面量

可以使用字面量、数组、对象以及可擦除的 TypeScript 类型语法，例如 `as const`。不能用函数调用、变量拼装、展开、运行时分支或模块副作用来生成 DSL。下面是故意非法的片段：

```js
const nextId = 'done';
// options中的next必须是可提取字面量；不能引用上面的运行时变量。
action('save', { name: '保存', action: 'save', next: nextId });
```

修复为 `next: 'done'`，重新运行 compile，确认不再出现 `FK_C007`。需要动态决定路线时，使用 [condition](/dsl/condition) 和初始 state；需要动态业务行为时，把代码放入宿主方法。

## 给宿主添加类型
