# 向 capability-graph 声明 FlowKit 能力

<a id="flowkit-doc-provider"></a>

实现与验证 [源码](https://github.com/devcodex-labs/flowkit/blob/main/src/integrations/capability-graph.mjs) · [类型](https://github.com/devcodex-labs/flowkit/blob/main/types/capability-graph.d.ts) · [测试](https://github.com/devcodex-labs/flowkit/blob/main/tests/integrations/capability-graph.test.mjs) · [示例](https://github.com/devcodex-labs/flowkit/blob/main/examples/docs/capability-graph/verify.mjs)

适用 FlowKit 1.0.0，示例验证使用 Capability Graph 2.1.1。使用能力 ID 查找结构化文档引用，按适用的 FlowKit 版本核对正文，然后决定宿主动作绑定。

FlowKit 通过 `@devcodex-labs/flowkit/capability-graph` 导出 `flowkitProvider`。它是一份满足 `capability-graph` Provider Schema v1 的**静态能力声明**，不是额外的执行器。

## 已声明的能力

| ID | 含义 |
|---|---|
| `flowkit::define-workflow` | 使用静态 JS/TS DSL 定义工作流 |
| `flowkit::compile-workflow` | 编译生成可执行 JS 与 Mermaid |
| `flowkit::check-workflow` | 检查定义及已有编译产物 |
| `flowkit::run-workflow` | 由显式提供的宿主 Runtime 执行 |
| `flowkit::render-mermaid` | 生成工作流可视化 |

## 用 Graph 查询

```js
import { CapabilityGraph } from '@devcodex/capability-graph';
import { flowkitProvider } from '@devcodex-labs/flowkit/capability-graph';

const graph = await CapabilityGraph.open({ providers: [{ definition: flowkitProvider }] });
try {
  const catalog = await graph.listCatalog();
  const details = await graph.getCapabilities({ ids: ['flowkit::run-workflow'] });
  const result = await graph.resolve({ ids: ['flowkit::render-mermaid'] });
  console.log(catalog.items.length, details.items.length, result.meta.completeness);
} finally {
  await graph.close();
}
```

Graph 的 `requires` 表示能力前置关系（例如 `render-mermaid` 需要 `compile-workflow`），**不决定工作流执行顺序**。FlowKit 自己的 `src/compiler/graph.mjs` 负责控制流图检查，与 Capability Graph 能力声明系统不是同一种图。

## 版本、权限与限制

Provider 声明版本、FlowKit 包版本、Graph SDK 版本和查询 `revision` 分别记录。当前映射的 Provider 声明版本为 1.0.3，适用开发中的 FlowKit 1.0.0。保留现有5项能力，不把 Agent 执行交给 Graph。`allowedProviders` 限定可见来源。`getCapabilities` 和 `resolve` 返回声明和关系，执行由提供绑定的宿主负责。描述型任务见[Runtime 契约](/reference/runtime#standard-task)，持久恢复见[Interactive 接入](/guide/interactive)，工具循环/独立主体/容量管理见[Host 接入](/guide/host-integration)。

如需将已解析能力绑定到业务操作，参见[宿主消费示例](/examples/capability-graph)。所有模型、动作权限和外部 IO 均由宿主提供。

## 读取能力文档 {#document-reading}

使用 `getCapabilities({ ids: ['flowkit::compile-workflow'] })` 取得 `capability.documents`。每条引用用稳定 `id` 标识。同一个页面可以关联到多项能力，例如编译和检查共用编译指南。先依据要执行的 FlowKit 版本选择文档；`usage.instructions` 提供简短的操作提示。

| 文档来源 | 谁读取 | 结果与失败条件 |
|---|---|---|
| `source.type: 'file'` | 注册时指定可信 `documentRoot`，再调用 Graph 的 `readDocument({ capabilityId, documentId })` | 返回 UTF-8 正文、`byteLength`、`contentHash`。路径出根、文件缺失或无法解码时拒绝 |
| `source.type: 'url'` | Graph 提供引用，`readDocument` 返回 `CG_DOCUMENT_REFERENCE_ONLY` | Host 对受信的固定 HTTPS 地址执行只读请求，验证状态、版本、字节和摘要 |

包内 Provider 提供指向固定文档提交的 HTTPS 引用。仓库内验证可用同一文档 ID 和仓库文档根登记 file 来源。Host 读取时留存 URL、文档提交、FlowKit 和 Provider 版本、Graph revision、字节摘要及读取时间。遇到重定向、不可达、版本或摘要不匹配，保留错误并停止使用这一文档。能力发现、文档读取和业务执行分别授权。

## 根据任务取得完整使用说明

五项声明是任务目录，不是全部字段或节点组合清单。按[编写工作流与能力选型](/guide/workflow-authoring)逐项找到参数、合法组合、模式、必要Host文件、错误和业务验收；仅拿到能力ID或requires不能推断流程已能执行。

特别注意：八类节点属于Standard；Interactive P0-A只接受其已实现子集，使用[独立Host契约](/guide/interactive)。运行依赖由Host提供，getContext等桥接默认值与类型见[API参考](/reference/sdk#createCapabilityGraphActionAdapter)。

Provider 内的能力 ID 是局部名，查询使用表中的 `flowkit::…` 完整 ID。网站可访问性、私有包取得和运行权限分别核实。遇到文档缺失、版本不符或缺少绑定，请先查明所缺条件。后续自然语言 Author 将按目标版本消费这些文档。
