# 项目介绍

FlowKit 是面向 Node.js 的工作流编排工具。你用 JavaScript / TypeScript DSL 描述节点和连接关系，编译器检查流程结构，再通过宿主 Runtime 执行 Agent、业务动作、验证和人工审批。

本文帮助你判断适用场景、理解各部分职责，并选择第一条学习路径。

## 什么时候使用

例如，一次内容交付包含“生成草稿 → 自动检查 → 不通过时修订 → 人工审批 → 交付”。每个步骤本身可以是现有函数或服务，流程定义负责说明下一步、失败后去哪里、何时结束。条件分流、独立并行检查、有限次数修复都可以明确写进流程。

如果只有一个直接调用的函数，你可以继续使用普通代码。FlowKit 的收益在于把多个步骤的控制关系变成可检查、可阅读、可生成图的定义。它不把任意 JavaScript 程序转换成工作流。

## 你编写的三类内容

| 内容 | 作用 | 最小例 |
|---|---|---|
| 工作流文件 | 声明节点、字段和引用；文件以 `.workflow.js` 或 `.workflow.ts` 结尾 | action 后接 terminal |
| 宿主 Runtime | 实现实际业务动作、模型调用、验证和人工交互 | `runAction` 把问候写入 `ctx.state` |
| Skill 文档 | 给 Agent 的指令文本；只在 Agent 场景需要 | 本地 Markdown 或受限制的 HTTPS 内容 |

`run` 可以直接执行工作流源码，也可以执行预先生成的 `.compiled.mjs`。编译器读取字面量定义，不执行工作流源码里的任意表达式。宿主仍是普通应用代码，可以按业务需求访问外部服务。

## FlowKit 和宿主的分工

| FlowKit 负责 | 你提供 |
|---|---|
| 结构和引用检查、受限条件表达式、生成控制流 | 流程定义与业务规则 |
| 节点执行顺序、Agent 重试、循环和审批分支 | 模型服务、业务接口、真正的审批交互 |
| 状态传递与节点约定的提交时机 | 初始数据、业务副作用及幂等策略 |
| 默认本地/远程 Skill 加载及一致性检查 | Skill 内容和允许的远程来源 |
| 把结果 Schema 交给宿主并处理校验结果 | 同步返回错误数组的 Schema 校验器 |

运行时不内置 JSON Schema 校验器，也不内置模型客户端。文档中的确定性宿主用于学习契约，会清楚标明如何替换为真实能力。

## 常用术语

- **工作流**：一个带 id、version、name 和 nodes 的定义。这里的 version 是你管理的业务流程版本，与 npm 包 v1.0.0 分开。
- **节点**：一次 Agent 任务、业务动作、验证或控制流步骤。`node()` 创建的类型是 `agent`。
- **宿主（Runtime）**：传给 `run` 的能力对象；每次运行都必须提供 `isControlSignal`，其他业务方法按节点需要提供。
- **运行上下文（Ctx）**：包含宿主、共享状态、取消信号和运行 ID 的对象。
- **编译产物 / AOT**：可阅读的 JavaScript 控制流。预编译部署仍需原始源码来校验一致性。
- **诊断 / 控制信号**：诊断描述定义或产物问题；控制信号用于取消等控制路径，不等同于普通业务失败。

## 边界先了解

状态以浅复制开始；嵌套对象仍可能与初始输入共享引用，并行分支使用同一份运行状态。`any` 返回不代表其他分支已停止。审批等待、持久化和重启后的恢复由宿主设计，不能依赖一个未提供的内置服务。

## capability-graph 的两个接入方向

FlowKit 可通过 `@devcodex-labs/flowkit/capability-graph` 提供静态 Provider 声明，供外部宿主发现能力；也能在宿主层使用 Graph SDK 解析能力、检查适用性与前置依赖，再通过显式绑定的动作执行。Graph 不负责工作流步骤排序、执行或持久化。[Provider 声明](/guide/capability-provider)与[真实宿主示例](/examples/capability-graph)分别验证这两条路径。

目前核心实现以 JS/TS DSL 为输入，不提供自然语言直接生成工作流的公共 API。模型若参与生成 DSL，其生成、审查与授权流程由宿主负责，不能把该组合写成 FlowKit 内置能力。

## 从哪里开始

先阅读[安装与环境](/guide/installation)，再按[第一个工作流](/guide/quick-start)完成两个文件的例子。你应先观察到实际成功状态、终点和写入值，再把动作替换为自己的业务函数。
