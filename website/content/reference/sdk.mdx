根入口 `@devcodex-labs/flowkit` 提供编译、检查、执行、条件计算和控制信号判断。构造工作流使用另一个入口 `@devcodex-labs/flowkit/dsl`。直接 SDK 以显式传入的 options 为准，CLI 配置文件供 CLI 使用。

## run：执行工作流 {#run}

```ts
run(file: string, runtime: Runtime, state?: Record<string, unknown>, options?: FlowkitOptions): Promise<RunResult>
```

file接受`.workflow.js`、`.workflow.ts`或`.compiled.mjs`，相对路径以调用时cwd为基准。runtime必须是对象且提供isControlSignal；state默认空对象，不能为null或数组。每次运行创建新Ctx和顶层浅复制state。正常到终点返回status、terminal和state；error仅在ctx实际拥有该属性时附加。未被结构处理的异常使Promise拒绝。

直接运行DSL会读取、编译并加载代码，但不生成同名compiled/mmd；dump可另外保存运行代码。AOT每次读取产物并验证源码/正文哈希，仍需物理源码。示例见[快速开始](/guide/quick-start)和[预编译与部署](/guide/aot)。

### 进程内缓存的精确边界

run每次重新读取指定源码或AOT。仅成功编译并首次加载的DSL代码进入进程内缓存，键包括：源码原始字节SHA256、绝对filename、解析后的projectRoot、skillsRoot（默认skills）、skillCheck（默认true）、**保留顺序的**remoteSkillHosts数组、trace（默认false）和解析后的dump路径或空值。

源码路径相同但字节改变，或上述任意键变化，都会选取另一项。remoteSkillHosts元素相同但顺序不同也不是同一个键。fetch、signal、runId和初始state不属于编译缓存键，它们属于各次执行。outDir/mermaid不影响run的内存编译产物。

编译错误与首次加载失败不会进入缓存；成功加载后业务运行失败不会删除已有编译项。因此重试业务仍使用已编译控制流，但创建新state/Ctx/默认Skill loader。Skill内容不包含在编译键中，下一次run仍读取新内容；同进程删掉Skill后，已有编译缓存可能让错误发生在运行加载阶段，独立check仍重新做编译检查。

这个缓存不保存业务结果或审批进度。默认最多 64 项、8 MiB 代码与键字节、5 分钟空闲 TTL，按 LRU 淘汰。Host 可从 `/host` 使用 `configureCompilationCache` 配置容量、`compilationCacheStatus` 观测命中/字节/淘汰、`clearCompilationCache` 清理编译项。

Node 的 ESM registry 不随 LRU 清理而卸载。Standard、Interactive 与 dump 共同限制进程级加载身份，默认 256 个及 64 MiB 程序 UTF-8 字节；失败加载和 dump 重试 URL 也占用身份。到限后新身份在加载前以 FK_R001 拒绝，原已加载身份仍可用。Host 应在达到预算前轮换自己的进程；`maxModuleIdentities`、`maxModuleBytes` 不能降低到已驻留数量/代码字节以下，清理不能重置该计数。字节容量只计可测代码与键，不冒充完整 V8 heap 限制。

## compile：编译文件 {#compile}

```ts
compile(file: string, options?: FlowkitOptions): Promise<CompileResult>
```

只接受DSL源码后缀，读取原始字节并静态提取，不执行源码中的任意代码。返回code、mermaid和diagnostics；无error时写compiled，默认写mmd。warning仍可写入。编译错误通过diagnostics返回；非法参数、文件I/O等可直接拒绝。已有产物不会因本次编译失败自动删除。

```js
const result = await compile('sample.workflow.js', { trace: true });
if (result.diagnostics.some(item => item.severity === 'error')) {
  throw new Error(JSON.stringify(result.diagnostics));
}
```

outDir必须为源目录或其祖先，参见[编译与检查](/guide/compile-artifacts)。不能把任意兄弟dist目录视为合法输出。

## compileSource：编译文本 {#compileSource}

```ts
compileSource(text: string, options: FlowkitOptions & { filename: string }): Promise<CompileResult>
```

text必须为字符串，filename必需且满足DSL后缀。filename提供输出路径、诊断位置与项目根查找依据；不要求对应源文件预先存在，但不会替你保存源码。副作用与compile相同。AOT运行仍验证物理源码，因此文本编译后部署必须另存原始文本并保持字节一致。

filename仅在这个函数的options中允许；传给run/compile/check或CLI配置属于未知选项。完整使用见下方api.mjs。

## check：检查源码与产物 {#check}

```ts
check(file: string, options?: FlowkitOptions): Promise<Diagnostic[]>
```

每次重新编译源码，不写文件。已有compiled时比较生成代码的完整字节，不一致附加FK_R001，诊断file指向该产物。compiled不存在时可成功返回空数组；mmd不会比较。它可用于源码检查，也可用于已有产物一致性检查，后者需要另外证明产物存在。

compile和check应使用相同的trace/路径/Skill设置。删除产物再check成功，不代表完成构建。

## evalWhen：计算条件 {#evalWhen}

```ts
evalWhen(ctx: Ctx, when: string): boolean
```

同步读取ctx.state并计算受限表达式。支持严格比较、布尔短路和自有属性路径；不做真假值转换。非法语法可抛FK_C032/033/034并带表达式列号，运行值类型错误为FK_R002。把此函数显式放入Runtime以支持condition。语法表见[条件表达式](/guide/conditions)。

## isControlSignal：识别控制信号 {#isControlSignal}

```ts
isControlSignal(err: unknown): boolean
```

同步判断控制标记，典型值为`{ control: true }`。用作Runtime的必需方法，区分取消等控制流与普通业务失败。不是所有AbortError都会自动变成此标记；宿主可按自己的取消协议扩展判定。控制信号不应被当成普通Agent失败反复重试。

## compileArtifact：生成正式 Standard 产物 {#compileArtifact}

`compileArtifact(file, options?)` 返回 `code`、`mermaid`、`artifactHash` 和 `diagnostics`，由调用方在批准发布步骤把 code 原样保存为 `workflow.js`。编译诊断包含错误时 `artifactHash` 为 null。

## runArtifact：执行已批准的产物 {#runArtifact}

`runArtifact(file, expectedHash, runtime, state?, options?)` 以可信批准记录持有的 `sha256:<hex>` 为预期身份，先核对文件字节和当前 Standard 模式、ABI 与语义版本，再执行。加载独立于父目录模块类型和源 DSL，身份或版本错误抛出 `FK_R001`。预期摘要须独立于待加载文件取得。

## 可选 capability-graph 子入口

`@devcodex-labs/flowkit/capability-graph` 单独导出 `flowkitProvider` 和 `createCapabilityGraphActionAdapter`。调用方安装并启动 Capability Graph，运行操作由宿主 Runtime 提供。详见[能力声明](/guide/capability-provider)和[宿主集成](/examples/capability-graph)。

### flowkitProvider {#flowkitProvider}

静态 Provider 声明包含 `schemaVersion: 1`、`providerId: 'flowkit'`、`name`、声明 `version`、`description` 和五项 `capabilities`。通过 `flowkit::…` 完整 ID 查询能力。`documents` 关联对应版本的文档，`usage.instructions` 提供操作提示，`requires` 说明能力前提。实际执行依赖宿主提供的动作绑定。Graph 实例由调用方关闭。字段及读取方式见[文档读取](/guide/capability-provider#document-reading)。

### createCapabilityGraphActionAdapter {#createCapabilityGraphActionAdapter}

同步构造`{runAction(action,name,ctx):Promise<void>}`，组合到Host的Runtime。参数对象如下：

| 字段 | 类型/必需/默认 | 约束与调用含义 |
| --- | --- | --- |
| graph | 必需GraphResolver | 由Host注入具有resolve函数的实例；不自动创建/安装Graph或模型 |
| bindings | 必需对象 | key对应DSL节点的action字段，不是节点id；每个顶层项须为数据属性，不接受accessor。构造时复制绑定值 |
| bindings[key].capabilityId | 必需string | 完整`provider::capability`，两段均以小写字母开头，后续为小写字母/数字/`._-` |
| bindings[key].execute | 必需函数 | 接收`{action,name,ctx,resolution,capability}`；同步void或`Promise<void>`。实际业务/写入及授权由Host承担 |
| getContext | 可选同步函数；默认`() => ({})` | 从ctx生成GraphContext（facts/notes等所需上下文）；返回非null对象、非数组，不能用异步Promise代替约定 |

省略getContext时传给Graph的是空对象，不是自动从state推导事实。对需要facts的能力，这不保证适用；Host应建立可信业务上下文。bindings的原对象后来被修改，不会更新已经复制的表；需要调整经审核绑定时重建相应适配器。

runAction先按action取绑定，再执行`resolve({ids:[capabilityId],context,relations:['requires']})`；要求complete、unresolved为空、包含所选根能力且全部解析节点applicability为applicable。随后await显式execute，只返回void，业务输出由Host回调按需求写ctx.state。解析不会替你执行依赖或生成业务函数。

构造参数违约同步抛TypeError；回调上下文不合约也可TypeError。调用时缺绑定为FK_CG_BINDING_MISSING，依赖不全/缺根为FK_CG_DEPENDENCIES_INCOMPLETE，不适用或适用性未知为FK_CG_NOT_APPLICABLE。GraphError及execute错误原样传播，不保证归一为FK_C/FK_R，也不回滚已发生的副作用。完整文件和正常失败处理见[Graph例](/examples/capability-graph)，类型见[完整声明](/reference/types)。

## 其他入口与版本

`/dsl`负责静态定义，[`/interactive`](/reference/interactive)提供另一套Host/Store/签收协议。`/package.json`导出包元数据，编译交付工具可用它核对版本，参见[prepare.mjs](/examples/direct-host)；它不提供新的工作流执行方法。直接模块、SDK源码与SDK AOT的依赖/上下文/结果差异见[执行路径表](/guide/direct-host)。
