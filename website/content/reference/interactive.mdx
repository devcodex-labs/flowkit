本参考对应 FlowKit 1.0.0 的 Interactive P0-A。Store、回执和程序身份需要满足现有契约；旧数据处置依[兼容范围](/community/compatibility)和具体迁移决策。

本页对应FlowKit 1.0.0的`@devcodex-labs/flowkit/interactive`。这些导出描述当前P0-A Host能力；发行/生产门禁和平台证据分别判断。先读[接口层选择](/guide/interactive)，可运行文件见[完整示例](/examples/interactive)。不要从dist私有路径导入实现。

## 编译与加载

### compileInteractive {#compileInteractive}

`compileInteractive(file, options)`返回Promise。file为`.workflow.js`或`.workflow.ts`路径，按调用时cwd解析，不接受DSL文本。非法参数/I/O可reject；编译问题返回diagnostics，使用code前检查error。

| options字段 | 必需/默认 | 行为 |
| --- | --- | --- |
| output | 必需：memory或file | memory只返回；file另写`<stem>.interactive.mjs`并返回artifactPath |
| featureStage | 必需：P0-A、P0-B 或 P1 | P1 支持 `all_succeeded` 下的并行请求 |
| targetVersion | 可省略；若给必须interactive-state-machine-v1 | 指定语义目标，不是软件包版本 |
| outDir | 源目录；相对cwd | file输出目录；不要套用Standard输出目录的所有限制 |
| projectRoot | 最近package.json所在目录，找不到回退cwd | 显式值按cwd解析；影响Skill检查 |
| skillsRoot / skillCheck | skills / true | 静态Skill根/存在性检查；不创建运行时Skill服务 |
| remoteSkillHosts | 空数组 | 编译允许的HTTPS主机；运行读取仍由Host负责 |

未知/Symbol字段、accessor及不合法类型不静默忽略。成功返回code、diagnostics、programIdentity；失败可返回空code且无identity。programIdentity包含artifact/source/workflow/compiler/ABI/semantics/checkpoint/canonicalization/stage身份，含义见本页完整类型。此接口不返回Mermaid；Standard编译图与Interactive执行产物不可互换。

静态诊断复用Standard分析器，编译器不下载远程Skill。skillCheck:false只跳过本地存在性检查，不放宽HTTPS白名单或integrity要求。flowkit.config.mjs由CLI读取，SDK不会隐式执行它。

### loadInteractiveProgram {#loadInteractiveProgram}

`loadInteractiveProgram(bytes, expectedArtifactHash)`验证Uint8Array产物及预期SHA-256并返回Promise，成功得到artifactHash、interactiveProgram、programTable、advance。Host应先从独立受信构建获得并固定哈希。此加载器和哈希检查不构成进程/OS沙箱，不接受Model指定的任意模块。

## 同步Store与Host内部协调器

### createSqliteCheckpointStore {#createSqliteCheckpointStore}

`createSqliteCheckpointStore(file, {namespace})`同步返回CheckpointStore；namespace必需。file指向Host私有SQLite文件，父目录和权限由Host准备；同名Run在不同namespace分别处理。结束调用close。数据库路径、WAL/SHM及存储故障边界见[Host与Store](/guide/interactive-host-store)。

| Store方法 | 输入/返回与责任 |
| --- | --- |
| putArtifact / getArtifact / deleteArtifact | 按programIdentity+bytes放入不可变产物，按哈希读取或尝试删除；被Run保留的产物不能任意清除 |
| createRun | startKey、可选startIntent、checkpoint；返回created及当前checkpoint。相同意图重试与冲突意图区分 |
| load | runId→checkpoint或null；保持完整执行信息，不把返回值直接发给Model |
| compareAndSwap | runId、expectedRevision、nextCheckpoint、transitionId及可选journalEntry；返回committed与checkpoint |
| listJournal | runId→经校验的审计链；空结果/损坏与成功读取区分 |
| getReceipt | runId+requestId→原acceptedRevision/digest等或null；用于历史接纳索引，不是业务结果仓库 |
| close | 释放连接；清理自己的临时文件另行处理 |

SQLite提供原子提交与索引实现；自定义Store须满足等效契约，不能用“写JSON后补Journal”替代原子CAS。该同步接口与下面CheckpointStoreV1不是同一返回形状。

### createInteractiveCoordinator {#createInteractiveCoordinator}

`createInteractiveCoordinator({store, runtime, policy?, maxStagesPerCall?})`返回协调器。policy默认空对象；maxStagesPerCall默认128，整数1–128，是单次推进预算，不是整个Run的步骤上限。返回policyHash和异步start/complete/resume/load。

Runtime按Agent需要提供skillResolver(descriptor)→字符串/Promise和同步validateResult(schema,result)→string[]。descriptor含runId、nodeId、name、agent/skill/integrity；Host负责按已批准来源读取和校验。本版Agent checkStep不支持，不能要求后静默跳过。

Skill必须是非空字符串，`instruction.length`不超过131072；这是JavaScript UTF-16代码单元数量，不是128 KiB字节上限。校验器必须同步返回可规范化的稠密JSON字符串数组，最多32项；每项非空，`reason.length`不超过512。`[]`表示通过；合约内的非空reasons按Agent声明的retries重试或耗尽，不能把校验器自身违约当普通业务校验失败。

| 绑定结果或错误 | 状态与处理 |
| --- | --- |
| Skill加载抛出code为FK_R014或FK_I_TEMPORARY_SKILL的错误 | paused，pauseReason为skill-temporary；Host处理临时来源问题后，用同Run的resume重试准备任务，未派发Agent |
| Skill加载抛出FK_R010/FK_R011 | errored并保留该causeCode，不按临时故障续跑 |
| 其他Skill异常、空文本或超长文本 | errored，causeCode为FK_I_SKILL_CONTRACT；修正Host绑定/来源后另行处理，不宣称原Run可恢复 |
| validateResult抛错、返回Promise、稀疏/不可规范化数组或超限/不合约reasons | errored，causeCode为FK_I_VALIDATOR_CONTRACT；保留原业务state，不走Agent retries |

Host应按实际临时故障分类映射允许暂停的code，不能把所有异常都伪装成可重试错误。版本化Runtime的implementation也受这些执行约束。

| 方法 | 输入 | 输出/限制 |
| --- | --- | --- |
| start | programBytes、programIdentity、startKey；可选runId/state/startIntent | 内部InteractiveRunFrame；可waiting、paused或终态 |
| complete | runId/requestId/nodeId/attempt，agent-result+result或agent-call-failed+failure.message | frame加acceptedRevision/duplicate；保留实际接纳语义 |
| resume | `{runId}` | 推进现有Run，沿用原产物/策略/Pending |
| load | `{runId}` | frame或null，不创建新Run |

这是Host内部接口，原始frame可包含state和单个pending；不含完整来源认证/模型披露边界。Model不能直接得到Store或complete能力。

同步Coordinator/Trusted Host会固定整个Host policy的指纹；Host可把经批准的Skill、校验器及其依赖版本声明放入policy.bindingVersions，并在Run生命周期保留对应实现。这是同步接口的Host约定，不是对任意JS闭包/可变资源的自动身份检测，也不是legacy Run的强制新字段。版本化接口另须满足下文policy.bindingManifest的描述符约束，不能用推荐的bindingVersions替代它。

协调器实例有4项LRU，仅缓存已验证的不可变Program对象，不缓存Store记录或进度。每阶段仍读取Host Store、验证当前产物字节/身份、策略与执行位置；缓存命中不能使已变更/缺失的产物合法。该缓存不跨实例共享，不提供延迟SLA。诊断脚本为仓库scripts/bench-interactive-load.mjs，性能样本不等于生产承诺。

## Trusted Host与签收

### createTrustedInteractiveHost {#createTrustedInteractiveHost}

`createTrustedInteractiveHost(options)`同步返回带Ed25519签收的Host外观；首发受控stdio使用此层。它校验Host固定的产物、策略、请求与签名，仍需独立OS权限和真实传输观察。

| 字段 | 必需/默认与约束 |
| --- | --- |
| store / runtime | Host持有的同步Store、上述InteractiveRuntime |
| trustedPublicKeys | 非空Ed25519公钥映射，最多32把；不传私钥 |
| trustedArtifacts | 非空受信artifactHash数组，最多1000项；来自独立受信构建 |
| allowedInputKeys | 默认空数组，最多256个不重复键；只允许Agent明确inputs中的白名单字段 |
| disclosurePolicyId / authorizeDisclosure | 必需；Host策略标识和授权回调，只有严格true允许披露 |
| policy | 默认空JSON对象；hostSecurity为外观保留字段 |
| authorizeTerminalAccess | 可选；未配置不允许终态投影/完整结果读；分别收到run:read或result:read动作 |
| authorizeReceiptAudit / authorizeKeyRevocation | 可选，缺失不授予管理权；撤销需支持持久信任的Store |
| drainOnly | 默认false；true仅承接现有Run，不新建 |
| maxProofAgeMs | 默认300000，1000–3600000整数毫秒，约束签名有效区间长度 |
| clockSkewMs | 默认5000，0–30000整数毫秒 |
| now | 默认Date.now；Host持有的时钟函数，不给Model控制 |
| maxStagesPerCall | 默认128，1–128，含义同协调器 |

提供start/resume/load、getPublicAgentTask、accept、getPublicTerminalFrame、readTrustedTerminalResult、readHistoricalAck、revokeKey、policyHash与securityMode。

`getPublicAgentTask({runId})`只返回经过inputs白名单和授权检查的任务，非waiting时可为null；不要序列化内部frame作为替代。`accept({receipt,attestation})`验证后才委托协调器接纳。终态先通过`getPublicTerminalFrame({runId})`得到不含state的resultRef，再由独立授权方调用`readTrustedTerminalResult({resultRef})`。

readHistoricalAck接收namespace/runId/requestId/nodeId/attempt/receiptHash，经receipt:read-history授权，只读原索引；revokeKey接收公钥SPKI SHA-256，经host:revoke-key授权在该Store撤销。撤销不能靠换keyId规避，也不会跨两个Store自动传播。完整历史Ack和新签名接纳是不同权限/行为。

### normalizeHostAgentReceipt {#normalizeHostAgentReceipt}

同步规范化JSON receipt，失败抛FK_I_PROVENANCE_REJECTED。共同字段是runId/requestId/nodeId/attempt及kind；agent-result带result，agent-call-failed带`failure:{message}`。只用Host已关联的当前请求/回调，不把Model声称的身份作为独立证据。

整个原始receipt的规范JSON上限为2 MiB，含元数据和结果封套；超限在Host accept的签名/来源验证前拒绝且不改变Run。runId/requestId/nodeId均为非空、最多256个JS代码单元的标识，不能含控制字符；attempt为1–11整数。failure.message必须非空且length不超过4096。超大原始回执、可信传输独立观测的输出超限和Checkpoint容量出口分别处理，见[三类分流与安全恢复](/guide/interactive-host-store#oversized-receipts)；不能把泛化来源拒绝当作可签署失败的证据。

### createAgentReceiptStatement {#createAgentReceiptStatement}

同步接收`{run, receipt, keyId, proofId, issuedAt, expiresAt}`，返回只读HostAgentReceiptStatement。run来自Host的权威Store，含namespace/artifactHash/policyHash；时间为正安全整数毫秒且expiresAt大于issuedAt。用于签名的keyId限1–64个协议字符，proofId限1–128，不能把任意字符串当合法标识。

语句绑定协议domain、key/proof、租户、Run、请求、节点/尝试、receipt种类、产物/策略/回执哈希与时间。该函数不持有私钥，也不证明真实模型调用。

### encodeAgentReceiptStatement {#encodeAgentReceiptStatement}

同步返回规范Uint8Array签名字节。Host用自己的Ed25519私钥签它；attestation为`{statement, signature}`，signature是规范base64url的64字节签名。不得自行JSON.stringify代替规范编码，也不得把私钥放进DSL、state或Model任务。新签收需满足时钟/有效期；已接纳的同字节重传按持久索引返回原接纳，仍验证签名和现行信任条件。

## 版本化Host接口

### createSqliteInteractivePersistence {#createSqliteInteractivePersistence}

`createSqliteInteractivePersistence(file,{namespace})` 返回 `{store, programRegistry, adminController, operationController, close}`。Store 的方法均为 Promise，见 CheckpointStoreV1。注册表负责按产物摘要注册和读取。

### 行为操作账本 {#operation-controller}

版本化 Host 的 Action Pending 带 `task.operationKey`。Host 以当前 Pending 的 Run、请求 ID、操作键及 `task` 的规范 JSON SHA-256 调用 `operationController.claim(input,auth)`。只有 `claimed:true` 表示本次取得派发权。对旧记录按原操作键核对外部结果。

`operationController.settle(input,auth)` 保存效果、证据摘要和结果，允许同内容重试。Action 的 `complete` 需要该账本的匹配结果。成功结果带 `set` 和可选 `remove`，字段须在该 Action 的 `writes` 中。Verification 成功回执结果为 `{passed:boolean}`，`false` 进入业务失败路径。

### cancelInteractiveRun {#cancelInteractiveRun}

`cancelInteractiveRun(runId,reasonCode,options)` 使用 `run:cancel` 权限封锁新派发。已派发操作可用独立的 `operation:read` 和 `operation:settle` 权限继续对账。

### P0-B 的 Loop、Human 和 Agent 校验

Loop 尝试次数随 Run 保存。最后一次 Verification 返回 `false` 时直接走耗尽路径。

操作员 Host 通过独立的 `authorizeHuman` 提供人工证明 `{proofId,evidenceHash}`。Human 回执包含当前 `task.reviewDigest` 和 `result:{approved,comment?}`。接纳事务记录主体、证据和被审内容。原主体可在当前 Run 权限下重取一份已接纳回执的确认。退回后进入源工作流修订路径，再次审阅生成新摘要。

P0-B 的版本化 Runtime 可绑定 `checkStep`（pure-local）和 `verifyAgentResult`（trusted-read）。`checkStep` 读取已提交状态，`verifyAgentResult` 读取未提交的候选状态。回调可根据 Run、请求和尝试标识重放同一读取，并接收取消信号。工作流声明 Agent `verify` 时，Host 必须绑定后者。Agent 首次解析的说明固定在本次激活，重试复用该说明。

### P1 并行

P1 的 `all_succeeded` 将同一 Run 的多个 Pending 同时公开。请求按自身 ID 和尝试接纳。其他分支的推进会改变 Run 修订，但不作废当前分支的请求。一条分支业务失败或技术错误后停止新派发。全部成功才一次性合并各分支补丁，实际字段写入有冲突时运行进入错误终态。

并行写入须在操作声明中提供同一业务效果的稳定 `businessKey`。API Agent adapter 使用 Host 工具的 `operationKey` 生成该键，且要求传入 `interactiveOperations:{controller,auth}`。Host 确认未取得派发权的 Action 可用 `FK_I_ACTION_NOT_DISPATCHED`、`sideEffectStatus:'none'` 提交失败，Store 会在接纳事务中检查该请求没有已登记操作。

putImmutable(bytes,programIdentity)返回TrustedProgramRefV1。产物引用有namespace、artifactHash和programId；保留/释放与Run持久引用一致，不能在Run仍引用时自行删产物。自定义实现必须保留R5封套全部字段以及原子创建/CAS、转换与回执对账契约；不要把公开frame当checkpoint存储。

### createInteractiveHostContext {#createInteractiveHostContext}

`createInteractiveHostContext({namespace,subjectId,authorize,authorizeTask})`返回不透明授权对象。四项必需；authorize判断run:create/run:complete/run:resume/result:read，authorizeTask逐次决定任务披露，两者只有严格true允许。工厂保存回调绑定，不能用展开/反序列化对象替代。它不自动从OS取得subjectId或证明生产身份。

### start {#start}

`await start(sourceOrRef, runtime, initialState, {...options,startKey})`。source字符串是Host已授权的**文件路径**，不是DSL文本；也可给受信注册表的Program引用。options含同namespace的store/programRegistry、policy和auth；startKey必需。同key/意图重试与意图冲突分开，已有Run恢复也需要授权。

RuntimeV1的skillResolver/validateResult为`{id,version,mode,implementation}`描述符，须与policy.bindingManifest一致。mode分别是trusted-read/pure-local；skillResolver收到reference和可选descriptor，校验器同步返回string[]；文本/reasons上限及paused/errored分流同上文绑定约束。policy还含id/version、disclosePolicyId、capabilityStage:P0-A、canonicalizationVersion:jcs-rfc8785-v1和可选requiredSkillManifestHash。不能把同步Runtime裸函数直接传进来。

maxStagesPerCall默认128，signal可选并需宿主协作。JSON状态和策略须能规范化，不能放函数、undefined、非有限数字或登录凭据。

### complete {#complete}

`await complete(submission,runtime,options)`是Host特权调用。成功submission仅有kind:'agent'、runId、requestId、outcome:'succeeded'及result对象；失败用outcome:'failed'及error对象，其code/message必需，retryable/origin可选。origin仅为runtime/executor/validator/store/policy之一。

Host先校验真实执行器来源并关联当前请求，再调用本接口；它不接受Trusted Host的attestation包，也不自动等价于Ed25519来源认证。结果的acknowledgement含requestId、acceptedRevision、repeated；同字节重试与不同内容冲突分别处理。

### resume {#resume}

`await resume(runId,runtime,options)`重用原Run/策略/绑定推进，不能改成另一个工作流“恢复”。返回公开InteractiveFrameV1：protocolVersion/runId/revision/status、pending数组、checkpointRef及按状态出现的terminal/resultRef/acknowledgement/diagnostics；不直接返回state。

### reserveInteractiveDispatch {#reserveInteractiveDispatch}

`await reserveInteractiveDispatch({runId,requestId,operationId},runtime,options)` 是 Host 内部的持久预算操作，需要当前 Run 的恢复权限及仍有效的 Task V2 授权。额外 API 请求发出前，按当前 Pending 的 requestId 和稳定 operationId 预留一次调度。重复操作幂等，原 deadline、总次数上限和资源绑定沿用检查点；不同 Pending、超预算和过期请求拒绝。同步协调器及 Trusted Host 的对应方法为 `reserveDispatch`，均不开放给模型。

完整结果用`auth.readTerminalResult(resultRef,options)`另经result:read授权取得。审计上下文可以只允许这个动作，不应把Model任务与完整状态读取合并。

读取支持succeeded、failed、errored和cancelled终态。succeeded/failed返回terminal；errored在持久封套含错误码时返回顶层causeCode，例如FK_I_VALIDATOR_CONTRACT或FK_R004，不能从可能为null的terminal读取它。不是每个终态都有causeCode，调用方应按status与实际字段处理。本例演示succeeded读取，错误终态、重开Store及授权拒绝由SDK回归覆盖。

结果读取仍逐次验证主体授权、namespace、policy与resultRef的Run/revision，只读当前终态，不推进Run或改写Checkpoint、Journal与接纳索引。读取失败时保留Run/resultRef并查证原因，不通过重提业务回执、重建Run或向Model开放原始Store处理。

### createInteractiveAdminContext {#createInteractiveAdminContext}

`createInteractiveAdminContext({namespace,subjectId,authorize})`建立独立管理上下文，供`adminController.adminTerminate(runId,reasonCode,auth)`授权终止。管理员主体/动作与运行、审计主体分别配置，取消后的旧Pending不能复活。它不是模型可提交的JSON对象，也不是自动创建OS管理员。

## 错误、版本与结构参考

普通参数违约可为TypeError/RangeError/I/O错误；编译error在diagnostics；权限或披露失败为FK_I_HOST_DENIED，签收来源失败为FK_I_PROVENANCE_REJECTED。未支持图/绑定、产物/策略失配、过期请求或回执冲突、CAS冲突、容量和存储异常须按实际code处理，不承诺全部包装成一个错误形状。

常用分类：FK_I_UNSUPPORTED_GRAPH/FK_I_BINDING_MISSING；FK_I_PROGRAM_MISMATCH/FK_I_POLICY_MISMATCH；FK_I_INVALID_RECEIPT/FK_I_STALE_RECEIPT/FK_I_RECEIPT_CONFLICT；FK_I_START_CONFLICT/FK_I_RUN_CONFLICT/FK_I_CAS_CONFLICT；FK_I_SKILL_CONTRACT/FK_I_VALIDATOR_CONTRACT及可暂停的FK_I_TEMPORARY_SKILL；FK_I_CHECKPOINT_CAPACITY；FK_I_STORE_UNCERTAIN/FK_I_STORE_CORRUPT/FK_I_STORE_SCHEMA/FK_I_STORE_UNSAFE。先保留当前Run及证据，确认持久结果后再重试；不能凭错误消息把未接纳请求写成已Ack。
