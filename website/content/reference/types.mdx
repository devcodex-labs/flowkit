# TypeScript 类型

公开类型与运行时函数位于两个入口：根入口提供SDK/Runtime类型，`@devcodex-labs/flowkit/dsl`提供DSL类型和构造器。使用TypeScript 5.0+；不要通过dist内部路径导入声明。

## SDK 类型索引

| 导出类型 | 字段/用途 |
|---|---|
| FlowkitOptions | 11项可选配置，类型/默认/适用矩阵见[配置参考](/reference/options) |
| Diagnostic | code可为string或null；message/file/line/column/severity必需，nodeId可选 |
| WorkflowResult | status为succeeded或failed，terminal为终点id |
| RunResult | 扩展WorkflowResult，含state和可选error |
| CompileResult | code、mermaid字符串和diagnostics数组 |
| Ctx | runtime/state必需，signal/runId/error可选 |
| AgentStep | id/name/instruction/input/missing/resultSchema/attempt/reasons必需，overview/signal/runId可选 |
| Runtime | 10方法与trace的start/end钩子；isControlSignal必需，业务方法按节点使用 |

## DSL 数据类型

| 导出类型 | 含义 |
|---|---|
| JsonValue | JSON标量、只读数组和字符串键对象；对象字段可含undefined以描述可选项 |
| JsonSchemaObject | 任意Schema关键词映射到JsonValue/undefined |
| ObjectSchema | JsonSchemaObject与必需type:'object'组合 |
| DeepReadonly | 递归只读映射，描述构造器返回的定义 |
| Retries | 0–10整数联合 |
| MaxIterations | 1–100整数联合 |
| AgentOptions | name/output与可选inputs/retries/verify/overview/integrity/next；agent/skill至少一个 |
| ActionOptions | name/action必需，writes/next可选，具体后继由上下文检查 |
| VerificationOptions | name/verifier必需，onSuccess/onFailure上下文决定 |
| ParallelOptions | name、至少2项branches元组、join.strategy/next |
| ConditionOptions | name、非空branches元组，每项when/next |
| LoopOptions | name/maxIterations/body/onSuccess/onMaxExceeded |
| HumanOptions | name/onApprove/onReject |
| TerminalOptions | name/status |

## 节点与工作流类型

AgentNode、ActionNode、VerificationNode、ParallelNode、ConditionNode、LoopNode、HumanNode、TerminalNode分别在对应Options上增加只读id和固定type。DslNode是这8类的联合；WorkflowDefinition包含id/version/name和只读nodes数组。

九个构造器返回保留字面量的只读定义。声明会检查未知字段、某些嵌套字段、已知id引用、并行成员后继和部分入口上下文。宽化成普通string或提前丢失字面量信息会降低静态检查能力；这不取消编译器的运行前检查。

## 消费者检查

```ts file="../../../examples/docs/sdk-options/consumer.ts" title="consumer.ts"
```

```sh
npm install --save-dev typescript@5.0.4 @types/node@22.13.0
npx tsc --noEmit --strict --skipLibCheck --target ES2022 --module NodeNext --moduleResolution NodeNext consumer.ts
```

该文件仅用于类型检查，不会自动运行工作流。对实际`.workflow.ts`文件同样执行tsc，再执行flowkit compile/check和宿主。输出Schema的业务正确性、远程响应、审批返回、并行副作用等不可能仅靠声明证明，必须运行对应案例。

## 遇到类型错误时

先核对入口、TypeScript版本和ESM设置；再查看是否多写字段、后继不存在、并行成员带next或联合类型不满足。避免用any或忽略诊断掩盖真实契约问题。完整JS/TS等价例见[JavaScript与TypeScript](/guide/javascript-typescript)。
