# TypeScript 类型

类型按根入口、`/dsl`、`/capability-graph`、`/interactive`、`/mcp` 和 `/host` 划分。根入口提供 SDK/Runtime 类型，`@devcodex-labs/flowkit/dsl` 提供 DSL 类型和构造器。使用 TypeScript 5.0+。MCP 的 `FlowkitMcpOptions` 描述 Host 绑定，`FlowkitMcpServer` 描述连接生命周期。普通 API 使用 `ApiHostTool` 和 `ApiHostOptions`。通过包声明入口导入类型。

## SDK 类型索引

Host 接入的 `ApiHostOptions`、`IndependentAgentOptions` 和 `CompilationCacheLimits` 分别描述模型传输、独立执行绑定和进程容量。`CompilationCacheStatus` 提供可观察计数；清理工具回执按 scope/Run 定位。MCP 的 `maxMetadataEntries` 和单页预算属于当前 Host 配置。Interactive 的 `PreparedAgentTask`、授权回调及持久 dispatch 预留见 [API](/reference/interactive)，不增加新的节点类型。

| 导出类型 | 字段/用途 |
|---|---|
| FlowkitOptions | 11项可选配置，类型/默认/适用矩阵见[配置参考](/reference/options) |
| Diagnostic | code可为string或null；message/file/line/column/severity必需，nodeId可选 |
| WorkflowResult | status为succeeded或failed，terminal为终点id |
| RunResult | 扩展 WorkflowResult，含内部 `state`、可选 `error` 和校验后的 `publicOutput` |
| CompileResult | code、mermaid字符串和diagnostics数组 |
| GraphSnapshotV1 | 同次静态编译生成的只读图，包含程序、源、模式、区域与契约身份 |
| GraphSnapshotEdge | 声明或派生边的稳定标识、起点、终点、角色与 sourcePath |
| InteractiveHumanDecision | 三结果 Human 的 `approve`、`revise` 或 `decline` |
| Ctx | runtime/state必需，signal/runId/error可选 |
| AgentStep | id/name/instruction/input/missing/resultSchema/attempt/reasons必需，overview/signal/runId可选 |
| Runtime | 10方法与trace的start/end钩子；isControlSignal必需，业务方法按节点使用 |

图的 `inputs` 只包含节点显式读取的键。`declared` 来自根输入 Schema，`inferred` 表示各到达路径都先提交了该 Human 的保留决定键，`conditional` 表示存在可能写入的上游节点，`unknown` 表示静态分析尚无来源证据。

## Standard Task 类型

| 类型 | 用途 |
|---|---|
| `TaskJsonValue`、`TaskJsonObject` | 任务与结果可序列化的 JSON 值域 |
| `AgentTaskV2`、`TaskPreparation`、`PreparedAgentTask` | 调用身份、Host 准备和实际派发 |
| `DescriptionRef`、`RequiredSkillRef`、`DescriptionResource`、`PreparedSkill` | DSL 逻辑引用与 Host 解析后的资源身份 |
| `ResourceManifest` | 已解析的资源顺序及内容摘要 |
| `CapabilitySupport`、`HostCapabilityProfile`、`TaskPolicy`、`HostPreparationContext` | Host 能力、授权、限制及本地 Prepare 上下文 |
| `SideEffectStatus`、`AgentExecutionResult` | 成功或失败结果、实际观察到的事件与 Usage |

## DSL 数据类型

| 导出类型 | 含义 |
|---|---|
| JsonValue | JSON标量、只读数组和字符串键对象；对象字段可含undefined以描述可选项 |
| JsonSchemaObject | 任意Schema关键词映射到JsonValue/undefined |
| ObjectSchema | JsonSchemaObject与必需type:'object'组合 |
| WorkflowContract | 工作流根级的可选 `input` 和 `output` 对象 Schema，执行前后由 FlowKit 校验 |
| DeepReadonly | 递归只读映射，描述构造器返回的定义 |
| Retries | 0–10整数联合 |
| MaxIterations | 1–100整数联合 |
| AgentOptions | name/output与可选inputs/retries/verify/overview/integrity/next；agent/skill至少一个 |
| ActionOptions | name/action 必需，支持 reads/writes/effect/next。Interactive 普通 Action 和子流程 Action 可声明 `onError`。 |
| VerificationOptions | name/verifier必需，onSuccess/onFailure上下文决定 |
| ParallelOptions | name、至少2项branches元组、join.strategy/next |
| ConditionOptions | name、非空branches元组，每项when/next |
| LoopOptions | name/maxIterations/body/onSuccess/onMaxExceeded |
| HumanOptions | name/onApprove/onReject；可通过 onDecline 和 maxRevisions 启用三结果审核 |
| TerminalOptions | name/status |

## 节点与工作流类型

AgentNode、ActionNode、VerificationNode、ParallelNode、ConditionNode、LoopNode、HumanNode、TerminalNode分别在对应Options上增加只读id和固定type。DslNode是这8类的联合；WorkflowDefinition包含id/version/name和只读nodes数组。

九个构造器返回保留字面量的只读定义。声明会检查未知字段、某些嵌套字段、已知id引用、并行成员后继和部分入口上下文。宽化成普通string或提前丢失字面量信息会降低静态检查能力；这不取消编译器的运行前检查。

声明文件中的NoExtra、References等未显式export辅助名称是推导实现，不作为额外受支持公共API；公开参数依赖的结构仍在声明中保留。上面列出的公开类型可由指定入口正常导入。

## 消费者检查

```ts file="../../../examples/docs/sdk-options/consumer.ts" title="consumer.ts"
```

```sh
npm install --save-dev typescript@5.0.4 @types/node@22.13.0
npx tsc --noEmit --strict --skipLibCheck --target ES2022 --module NodeNext --moduleResolution NodeNext consumer.ts
```

上面的`tsc --noEmit`只检查类型，不执行consumer.ts；该文件含顶层run，转译后执行或导入会运行工作流，需准备对应文件与Runtime。对实际`.workflow.ts`文件同样执行tsc，再执行flowkit compile/check和宿主。输出Schema的业务正确性、远程响应、审批返回、并行副作用等不可能仅靠声明证明，必须运行对应案例。

## 遇到类型错误时

先核对入口、TypeScript版本和ESM设置；再查看是否多写字段、后继不存在、并行成员带next或联合类型不满足。避免用any或忽略诊断掩盖真实契约问题。完整JS/TS等价例见[JavaScript与TypeScript](/guide/javascript-typescript)。

## Interactive类型与不透明上下文

`/interactive`的全部显式类型、各层输入/返回、Store/ProgramRegistry与Runtime描述符见[Interactive API](/reference/interactive)。不要把同步frame、版本化pending数组或签收协议混用；Host/Admin上下文通过工厂取得，不能用JSON伪造。包的`/package.json`是元数据入口，可用于核对版本，不是另一个执行接口。
